# Требования к API

- Следует придерживаться классических правил REST API
- В url используем kebab-case: `https://host:port/payment-limit/api/v1/check-operation`
- Для бизнес логики в пути обязательно добавлять префикс с наименованием сервиса и версией эндпоинта:
  `/payment-limit/api/v1`
- Для имен query параметров используется camelCase: `/payment-limit/api/v1/operations?operationId=12345`
- Для enum значения используется UPPER_SNAKE_CASE:
```json
{
  "data:": {
    "triggerType": "TICKET_CLOSED"
  }
}
```

## Единый формат запроса

CommonRequest:
```json
{
  "data": {
    // полезная нагрузка запроса
  }
}
```

### Запрос при фильтрации:

CommonRequest:
```json
{
  "data": {
    "filter": {
      // параметры фильтрации (например startDateFrom, namePart и т.д.)
    },
    "paging": {
      "offset": 50,
      "limit": 20
    },
    "order": [
      {
        "sortBy": "create_time",
        "orderBy": "DESC"
      },
      {
        "sortBy": "operation_id",
        "orderBy": "ASC"
      }
    ]
  }
}
```

GET запрос с пагинацией:
```
https://host:port/payment-limit/api/v1/operations/12345?limit=20&offset=20&sortBy=create_tyime&orderBy=DESC
```

## Единый формат ответа:

- Допустимы только статусы 200, 400, 401, 403, 404, 500
- При статусе 200 ответ всегда успешный
- Статус 400 возвращается при исключениях бизнес логики, которые заранее определены аналитикой и разработкой
- Статус 500 возвращается при непредвдиенных исключениях в работе приложения

CommonResponse (сопровождается 200 статусом ответа):
```json
{
  "id": "9a28c941-cec6-40e3-b887-e979d58773da", // Уникальный идентификатор ответа, может быть случайным, необходим для удобства поиска по логам
  "timestamp": "2025-12-09T13:30:00Z",          // в UTC таймзоне
  "data": {
    // Полезная нагрузка ответа
  }
}
```

CommonResponse при возврате ответа со списком элементов (сопровождается 200 статусом ответа: 
```json
{
  "id": "195163f6-73ae-4ac9-aeb8-638152c5a1e6", 
  "timestamp": "2025-12-09T13:30:00Z",
  "data": {
    "itemsCount": 2,
    "totalCount": 10,
    "items": [
      // ...
    ]
  }
}
```
В случае возврата списочных значений, они дополнительно оборачиваются в ключ items, также может добавляться поле itemsCount (для обозначения возвращаемого количества записей), и totalCount (для обозначения общего количества записей на всех страницах)

CommonResponse при ошибках валидации (сопровождается 400 статусом ответа):
```json
{
  "id": "9a28c941-cec6-40e3-b887-e979d58773da",
  "timestamp": "2025-12-09T13:30:00Z",
  "data": {
    // Полезная нагрузка ответа, при наличии
  },
  "error": { 
    "location": "00a24665", // Уникальный идентификатор ошибки, для удобства определения места возникновения ошибки на бекенде (необязательное поле)
    "code": "validation",   // Человекочитаемый код ошибки
    "message": "Ошибка валидации",
    "validations": [
      {
        "path": "body.description",
        "message": "Описание не может быть короче 3 символов"
      },
      {
        "path": "body.description",
        "message": "Описание содержит недопустимые символы"
      },
      {
        "path": "body.user.firstName",
        "message": "Имя пользователя не может быть пустым"
      }
    ]
  }
}
```

CommonResponse при бизнес ошибках (сопровождается 400 статусом ответа):
```json
{
  "id": "34ad158f-26d1-44fa-97e0-44687aaea6e6",
  "timestamp": "2025-12-09T14:30:00Z",

  "error": { 
    "location": "ea515bcc",

  }

```

CommonResponse при критических ошибках (сопровождается 500 статусом ответа):
```json
{
  "id": "855528c7-2a39-48ae-9358-a032cf901925",
  "timestamp": "2025-12-09T14:30:00Z",
  "data": {
```

## Обработка ошибок при межсервисном взаимодействии

В цепочке `фронт → сервис 1 → сервис 2 → сервис 3` действует принцип прозрачности:
- **Бизнес-ошибки** (например "Пользователь не найден") — пробрасываются до фронта с оригинальным сообщением
- **Технические ошибки** (например `NullPointerException`) — скрываются от фронта, показывается generic-сообщение

### Маршрутизация ошибок downstream

| Тип ошибки downstream                    | HTTP-статус | Поведение                                | Что видит фронт                                    |
|------------------------------------------|-------------|------------------------------------------|----------------------------------------------------|
| Бизнес-ошибка (4xx)                      | 400         | Пробрасываем `displayMessage` as-is      | Оригинальное сообщение от downstream               |
| Таймаут                                  | 400         | `BusinessException` с generic-сообщением | "Сервис временно недоступен, попробуйте позже"     |
| Техническая ошибка (5xx)                 | 500         | `CriticalException` с generic-сообщением | "Сервис временно недоступен, попробуйте позже"     |
| Транспортная ошибка (connection refused) | 500         | `CriticalException` с generic-сообщением | "Сервис временно недоступен, попробуйте позже"     |
| Непредвиденная ошибка                    | 500         | `CriticalException` с generic-сообщением | "Что-то пошло не так, обратитесь к администратору" |
